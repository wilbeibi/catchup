catchup / continue a Codex session in Claude Code

How to continue a Codex session in Claude Code

Run catchup fork codex --into claude. It reads the newest Codex session in the current directory, strips the tool calls and reasoning traces, and starts Claude Code with the remaining conversation as its opening prompt. Claude Code picks up knowing what was already decided.

$catchup fork codex --into claude

What crosses, and what doesn't. Going from one agent to another carries the conversation, not native session state. Claude Code opens a new session seeded with the Codex transcript. Nothing recreates Codex's internal state inside Claude Code, and no tool ever could — the two store different things in different formats.

Keeping the prompt small

Codex sessions get long. Trim the transcript before it becomes Claude Code's opening prompt:

$catchup fork codex --into claude --last 20
  • --last 20 — only the last 20 exchanges.
  • --since-compact — only the tail after the last compaction.
  • --model <name> — launch Claude Code on a specific model, passed through as-is.

Choosing which Codex session

The default is the most recent Codex session in the current directory. To pick another:

$catchup codex -q "migration"

-q searches by keyword and lists what matches; codex/3 selects the third-newest; --id <id> takes an exact session id; --dir <path> reads sessions from another directory. See finding an older session.

Restarting the same agent cleanly

If you want Codex itself to continue but with a fresh, smaller context rather than its accumulated one, point --into back at the same agent:

$catchup fork codex --into codex --since-compact

That restarts Codex clean, seeded with just the recent work. To instead resume with Codex's real session state, drop --into and run catchup fork codex — see the comparison.

Questions

Does Claude Code get the real Codex session state?

No. Crossing agents carries the transcript, not native session state — Claude Code starts a fresh session whose opening prompt is the Codex conversation. Native state is preserved only when you resume the same agent, with catchup fork codex.

Can I send only part of the Codex session?

Yes. --since-compact keeps only the tail after the last compaction and --last <N> keeps the last N exchanges. Both compose with --into, so the target agent starts on a smaller prompt.

Which agents can be the source or the target?

Any supported agent on either end: Claude Code, Codex, Cursor, Cline, Kimi, Antigravity (agy), OpenCode, and Pi Agent. The form is always catchup fork <source> --into <target>.
