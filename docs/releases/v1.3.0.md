# v1.3.0

Recover conversations from Cursor IDE and Grok Bot's desktop cache.

## Cursor IDE history

`cursor` now reads desktop IDE conversations alongside CLI sessions. It keeps
mid-turn user messages and failed commands that the IDE's JSONL export omits.

```bash
catchup cursor --list --all-dirs
catchup cursor --id ide:SESSION_ID --show tools
catchup fork cursor --id ide:SESSION_ID --into codex
```

IDE session IDs start with `ide:`; CLI IDs and native CLI resume stay unchanged.
Continue an IDE session inside Cursor, or hand its transcript to another agent
with `--into`. IDE compaction boundaries and API stop events are unavailable.

CLI history remains readable when the desktop database cannot be read, with a
warning on the recovered transcript. Searches include successful tool calls
only when you pass `--show tools`.

## Grok Bot desktop cache

The new `grokbot` provider reads conversations cached for the active desktop
account. `grok` continues to mean Grok Build.

```bash
catchup grokbot --all-dirs
catchup fork grokbot --all-dirs --into codex
```

Use `--all-dirs`: these chats have no local project directory. The cache can
omit older messages, tool failures, non-text content and compaction history;
catchup reports these limits in warnings. Selecting a conversation with `--id`
does not require unrelated replicas to use a supported schema.

Native launch and local skill installation are unavailable for Grok Bot.
